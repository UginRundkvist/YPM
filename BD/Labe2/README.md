# База ED_SALES — восстановление из выгрузки

## Что было в выгрузке

`table_rows.txt` — метаданные (имена колонок, типы, длины) по 8 таблицам.
8 CSV-файлов — сами данные. Итого:

| Таблица | Строк |
|---|---|
| ОТДЕЛЫ | 4 |
| УРОВНИ_ЗАРПЛАТЫ | 5 |
| КЛИЕНТЫ | 10 |
| ПРОДУКТЫ | 7 |
| СОТРУДНИКИ | 23 |
| ЗАКАЗЫ | 11 |
| ПОЗИЦИИ | 17 |
| ЦЕНЫ | 21 |

Выгрузка содержит **только данные и типы колонок** — ключей и ограничений в ней нет.
Их пришлось восстановить по смыслу и проверить на фактических данных.

## Какие ключи поставлены

Первичные ключи — там, где данные действительно уникальны (проверено):

| Таблица | PK |
|---|---|
| ОТДЕЛЫ | НОМ_ОТДЕЛА |
| УРОВНИ_ЗАРПЛАТЫ | УРОВЕНЬ |
| КЛИЕНТЫ | НОМ_КЛ |
| ПРОДУКТЫ | НОМ_ПРОД |
| СОТРУДНИКИ | НОМ_СОТР |
| ЗАКАЗЫ | НОМ_ЗАК |
| ПОЗИЦИИ | НОМ_ЗАК + НОМ_ПОЗ |
| ЦЕНЫ | **нет** |

У ЦЕНЫ естественный ключ — (НОМ_ПРОД, ДАТА_Н), но в данных есть дубль:
товар 100860 дважды с ДАТА_Н = 01.01.1996 (строки с ценами 250.5 и 225).
Поэтому PK там не объявлен — иначе скрипт не загрузился бы.

Внешние ключи — только те, что выдерживают данные:

- ЗАКАЗЫ.НОМ_КЛ → КЛИЕНТЫ
- СОТРУДНИКИ.НОМ_ОТДЕЛА → ОТДЕЛЫ
- ПОЗИЦИИ.НОМ_ЗАК → ЗАКАЗЫ

Не объявлены, потому что в данных есть ссылки «в пустоту»:

- СОТРУДНИКИ.НОМ_НЛНК → СОТРУДНИКИ (начальник): у КИНГа стоит 0, у АДАМСа — 7788, такого сотрудника в таблице нет
- ПОЗИЦИИ.НОМ_ПРОД → ПРОДУКТЫ: заказаны товары 100870, 101863, 102130, 200380, которых в ПРОДУКТЫ нет
- ЦЕНЫ.НОМ_ПРОД → ПРОДУКТЫ: цены есть на 100870, 101860, 101863, 101890, 102130, 200380 — тоже отсутствуют

Это не ошибка восстановления, так в самой учебной базе. Полезно помнить при запросах:
соединение ПОЗИЦИИ с ПРОДУКТЫ через `INNER JOIN` молча потеряет часть строк, нужен `LEFT JOIN`.

## Как поднять

```bash
bash install_oracle.sh
```

Скрипт сам поставит Docker (если его нет), поднимет Oracle Free 23 и зальёт схему.
Если Docker ставился впервые — скрипт попросит выполнить `newgrp docker` и запустить его ещё раз.

## Подключение из SQL Developer

| Поле | Значение |
|---|---|
| Username | ED_SALES |
| Password | ed_sales |
| Hostname | localhost |
| Port | 1521 |
| Тип | Service name (не SID) |
| Service name | FREEPDB1 |

Админский вход, если понадобится: `SYSTEM` / `oracle`.

Контейнер живёт между перезагрузками: `docker start oracle-bd` — данные на месте.

## Если что-то пойдёт не так

- `ORA-00904` или `ORA-00911` при создании таблиц — Oracle не принял кириллицу в именах без кавычек. Напиши, пересоберу скрипт с `"КЛИЕНТЫ"` в кавычках.
- Кракозябры вместо русского — в SQL Developer: Tools → Preferences → Environment → Encoding = UTF-8.
- Порт 1521 занят — поменяй в `install_oracle.sh` на `-p 1522:1521` и подключайся на 1522.
