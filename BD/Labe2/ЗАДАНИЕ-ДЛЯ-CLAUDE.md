# Задача для Claude Code

Подними локально Oracle в Docker и залей в него учебную базу `ED_SALES`.
Всё нужное уже лежит на диске, писать SQL с нуля не надо.

## Контекст

База живёт в вузовской сети, из дома недоступна. Одногруппник сделал выгрузку
(8 CSV + файл с типами колонок), по ней уже собран рабочий SQL-скрипт.
Цель — чтобы база крутилась локально и к ней подключался Oracle SQL Developer:
дальше по ней надо писать запросы для лабораторной №2.

## Что уже есть

Папка `~/Документы/BD_lab2`:

| Файл | Что это |
|---|---|
| `ed_sales_oracle.sql` | схема + данные для Oracle. **Готов, менять не надо** |
| `install_oracle.sh` | разворачивание в один запуск |
| `ed_sales_pg.sql` | тот же дамп под PostgreSQL — запасной вариант |
| `README.md` | описание базы и особенностей данных |

Скрипт `ed_sales_oracle.sql` проверен: грузится без ошибок, 8 таблиц, 98 строк.

## Что сделать

```bash
cd ~/Документы/BD_lab2
bash install_oracle.sh
```

Скрипт сам: поставит Docker при необходимости → поднимет контейнер
`oracle-bd` из образа `gvenzl/oracle-free:23-slim` на порту 1521 →
дождётся строки `DATABASE IS READY TO USE` в логах → скопирует SQL внутрь
контейнера → прогонит его через `sqlplus` под `system/oracle@localhost:1521/FREEPDB1`.

Если Docker ставился впервые, скрипт выйдет с просьбой выполнить `newgrp docker` —
тогда запусти его ещё раз.

### Критерий успеха

В конце `sqlplus` печатает таблицу. Должно быть ровно так:

```
ЗАКАЗЫ            11
КЛИЕНТЫ           10
ОТДЕЛЫ             4
ПОЗИЦИИ           17
ПРОДУКТЫ           7
СОТРУДНИКИ        23
УРОВНИ_ЗАРПЛАТЫ    5
ЦЕНЫ              21
```

Если сошлось — задача выполнена. Доложи параметры подключения (ниже) и остановись.

## Параметры подключения (для SQL Developer)

```
Username : ED_SALES
Password : ed_sales
Hostname : localhost
Port     : 1521
тип      : Service name  (НЕ SID)
Service  : FREEPDB1
```

Админ: `SYSTEM` / `oracle`.

## Важно: чего НЕ делать

Эти «недочёты» в скрипте сделаны намеренно, под фактические данные выгрузки.
Не надо их «исправлять» — с исправлениями скрипт перестанет грузиться.

1. **У таблицы `ЦЕНЫ` нет первичного ключа.** По смыслу это `(НОМ_ПРОД, ДАТА_Н)`,
   но в данных товар `100860` дважды лежит с `ДАТА_Н = 01.01.1996`.
2. **Объявлены только 3 внешних ключа** (`ЗАКАЗЫ→КЛИЕНТЫ`, `СОТРУДНИКИ→ОТДЕЛЫ`,
   `ПОЗИЦИИ→ЗАКАЗЫ`). Ещё три связи не объявлены, потому что ссылаются в пустоту:
   - `СОТРУДНИКИ.НОМ_НЛНК` → у КИНГа `0`, у АДАМСа `7788` (такого сотрудника нет)
   - `ПОЗИЦИИ.НОМ_ПРОД` → товаров `100870, 101863, 102130, 200380` нет в `ПРОДУКТЫ`
   - `ЦЕНЫ.НОМ_ПРОД` → плюс к ним нет `101860, 101890`
3. **Имена таблиц и колонок — кириллицей, без кавычек.** Так в исходной базе.
   Не переводи в латиницу: уже написанные запросы перестанут работать.

Не удаляй CSV или сам SQL-скрипт, не пересобирай схему своими силами.

## Если не заработает

| Симптом | Что делать |
|---|---|
| `ORA-00904` / `ORA-00911` на `CREATE TABLE` | Oracle не принял кириллицу без кавычек — сообщи, скрипт пересоберут с `"КЛИЕНТЫ"` в кавычках |
| не дождался `DATABASE IS READY TO USE` | `docker logs oracle-bd` — скорее всего мало места или памяти; покажи хвост лога |
| порт 1521 занят | в `install_oracle.sh` поменяй `-p 1521:1521` на `-p 1522:1521`, подключение тогда на 1522 |
| образ не качается | проверь сеть/DNS; при полном отказе откатывайся на `ed_sales_pg.sql` + PostgreSQL, но это хуже: преподаватель проверяет на Oracle |
| кракозябры вместо русского | `sqlplus` должен запускаться с `NLS_LANG=.AL32UTF8` (в скрипте уже так) |

## Управление контейнером

```bash
docker stop oracle-bd     # остановить
docker start oracle-bd    # включить, данные на месте
docker rm -f oracle-bd    # снести совсем
```
